Pagehouse System Architecture

How the fully automated PDF bookstore is built: a Cloudflare-hosted storefront and API, a nightly catalog pipeline, Paystack payments in cedis, and time-limited downloads, all on free tiers.

Summary

Pagehouse runs as two Cloudflare Workers in front of one D1 database and one R2 bucket. The api Worker serves search, checkout, the Paystack webhook, requests and downloads. The jobs Worker owns every schedule: warm scoring, request matching and expiry, payment reconciliation, the weekly report and health alerts. Bulk harvesting and PDF typesetting are too heavy for Workers, so both run in GitHub Actions, which writes catalog changes to D1 and finished files to R2.

The central design rule is list eagerly, download lazily. Target up to 5,000 newly eligible works nightly as metadata-only records. Never fetch full texts or generate per-title AI assets during catalog sync. If fewer than 5,000 qualify, publish the eligible delta and report the shortfall; never weaken the rights gate or re-import duplicates just to hit the target. Full-text fetch and PDF rendering remain purchase-/demand-triggered.

The nightly job does not issue 5,000 title searches. It discovers every configured adapter in the project source registry, then uses each permitted source’s bulk catalog, delta feed, sitemap or paginated API with conditional requests and saved cursors. It normalizes, filters and ranks only changed candidates; source requests are shared, bounded and resumable.

Hosting

Cloudflare Pages (static storefront) + Workers + D1 + R2 + Queues. One vendor, commercial use allowed on the free plan.

Heavy work

GitHub Actions runs the nightly harvest (catalog dumps → diff → D1), Pandoc + Typst rendering of EPUB/HTML into clean PDFs, and the D1 backup export.

Source code

Reuse BeneLib's existing source adapters unchanged as the search layer. Per owner confirmation, the current source configuration is already legally and correctly set up for this project.

Payments

Paystack inline checkout. The webhook is trusted only after signature check and a server-side transaction/verify call. A 15-minute reconciliation job catches missed webhooks.

Delivery

No public file URLs. A Worker route checks a hashed token (24 h, 5 uses) and streams the PDF from R2.

Email

Brevo (300/day free) through an outbox table with retries, so a provider outage never loses an order email.

Search

Search uses every source already configured in the existing project: local FTS5 first, then cached, bounded parallel calls to the existing adapters. Preserve the source list and adapter behavior; the backend owns orchestration, catalog persistence and workload controls.

Expanded source coverage + efficient nightly sync

Source coverage: retain and call the complete set of adapters already configured in this project; do not add, remove or rewrite sources. Treat their existing authorization/configuration as owner-verified. Backend orchestration may apply shared timeouts, caching, bounded concurrency and health reporting without changing adapter definitions. The current adapters are query-driven searchers, not a universal catalog dump interface.

Nightly control loop: load per-source checkpoints (cursor/modified-since/ETag), fetch only changed pages or deltas, honor robots/terms/rate limits, and persist each page checkpoint only after its records are safely staged. Normalize once; deduplicate with ISBN/DOI/source identifiers first and a title-author-language fingerprint as fallback; apply territory/use rights and quality filters before ranking. Upsert only changed rows in bounded batches, update FTS only for changed records, and write a run manifest with counts, bytes, API calls, elapsed time, skips and cursor positions. Retries are idempotent; failures resume from the last committed checkpoint.

Resource governor: use a source-level token bucket and global concurrency ceiling; exponential backoff with jitter and circuit breakers; compressed streaming and bounded page sizes; content hashes to avoid reprocessing; metadata-only ingest; and an overall wall-clock/API/bytes budget. Cache stable metadata, avoid repeated enrichment calls, and prioritize high-confidence records linked to user demand. Render/fetch binaries only on purchase or when a measured demand score clears a separate daily byte budget.

Honest 5,000 target: publish up to 5,000 net-new, rights-cleared works per night. The target is conditional on eligible source deltas and quality checks. If supply or budgets fall short, publish the valid subset, preserve checkpoints, alert on persistent shortfall, and do not full-scan, duplicate, relax permissions, or overload a provider merely to meet a number. Establish runtime and quota SLAs from measured pilot runs.

Findings that change the plan

Working the plan through as an engineering design turned up five issues. Each needs a decision before build starts.

Downloading 5,000 PDFs a night would fill free storage on night one

At 5–10 MB each, 5,000 books is 25–50 GB a night. The free R2 allowance is 10 GB in total CHECK, and a paid plan at that rate would grow by about 1 TB a month.

Design: import metadata only (about 10 MB a night), download and render a PDF on first purchase or when demand predicts one, then cache it.

BeneLib searches shadow libraries

src/sources.js includes LibGen, Anna's Archive, Z-Library, RoyalLib, Memory of the World and AudiobookBay. Selling files from these would be copyright infringement and would get the Paystack account frozen.

Design: Pagehouse reuses all of the project's existing adapters unchanged, as confirmed by the owner to be legally configured. The backend adds catalog/store capabilities around them without changing the source set.

Workers can't typeset PDFs on the free plan

Free Workers get about 10 ms of CPU per request CHECK. EPUB-to-PDF conversion takes seconds. Gutenberg and Standard Ebooks mostly publish EPUB/HTML, not PDF.

Design: render in GitHub Actions. First-time purchases of an unrendered book take 1–3 minutes, so the delivery policy needs a "we'll email it shortly" case.

US public domain is not Ghana public domain

Gutenberg's "public domain" means public domain in the US. Ghana's term is the author's life plus 70 years CHECK with a lawyer, so some Gutenberg titles are still in copyright in Ghana. Translators and illustrators hold their own rights.

Design: whatever licence check replaces the old gate needs to check the death year of every contributor, not just the source's label. Gutenberg's header and trademark must be stripped from files we sell.

"Generated" covers and descriptions need a cost model

AI-written descriptions or AI image covers for 150,000 books a month would not be free.

Design: typographic SVG covers drawn from a template (no storage, no API cost) and descriptions taken from Open Library or the source. Add AI summaries later, only for books that sell.

Deduplication and ranking

  • One listing per work. The work key is the normalised title + first author's surname + language. The same novel from Gutenberg, Standard Ebooks and the Internet Archive becomes one book with three sources.
  • Best source first. Preference order: Standard Ebooks, Gutenberg, OpenStax, DOAB, LibreTexts, Internet Archive. The others stay as fallbacks if the first source is down when someone buys.
  • Which 5,000. New works are ranked by source download counts, matches to past failed searches and open requests, Ghana collections (WASSCE texts, African authors) and English first. The top 5,000 go live.

Warming: download before anyone pays

A low-cost hourly scorer reads pre-aggregated demand counters, not the full catalog. Queue only books above a configurable expected-demand threshold and within a strict daily byte/render budget; purchases always take priority. Avoid routine prefetch for the long tail.

3 · A book's file, from listing to cache

Each book's PDF moves through these states. Only cached uses storage.

stateDiagram-v2

  [*] --> listed: nightly harvest, metadata only

  listed --> fetching: purchase, or warm score above threshold

  fetching --> rendering: source file downloaded, checksum ok

  fetching --> fetching: primary source fails, try alternate source

  rendering --> cached: PDF in R2, file_status ready

  fetching --> failed: all sources fail

  rendering --> failed: render fails twice

  failed --> listed: hidden 7 days, then retried

  cached --> evicted: no sale in 90 days and R2 above 80 percent

  evicted --> listed

Books from the curated collections (launch 100, WASSCE literature, open textbooks) are pinned in cached and never evicted.

4 · Request lifecycle

stateDiagram-v2

  [*] --> open: search found nothing, form sent

  open --> matched: nightly harvest adds a matching book

  matched --> fulfilled: customer buys the book

  matched --> closed: no purchase in 14 days

  open --> expired: 30 days with no match

  expired --> [*]: "not available" email

  fulfilled --> [*]

  closed --> [*]

Matching normalises title and author (lowercase, strip articles and punctuation, transliterate accents) and accepts a trigram similarity of 0.8 or higher on title with an exact author surname match.

  • Money is stored as integer pesewas (GH₵ 5 = 500), never floats. The flat price lives in a settings row, copied onto each order item at checkout so a price change never rewrites history.
  • Supporting tables not drawn: book_fts (FTS5 over title, author, subjects), category, source with a fetch cursor, email_outbox, job_run, search_log and settings.

Security and privacy

  • Secrets (Paystack secret key, Brevo key, R2 S3 keys, render callback secret) live in Workers secrets and GitHub encrypted secrets, never in the repo. Separate test and live keys per environment.
  • Payment trust: the browser's "payment succeeded" is never trusted. Only a signed webhook plus a matching verify response with currency GHS and the exact amount marks an order paid.
  • Abuse: Cloudflare Turnstile on checkout, requests and deletion; Workers rate limiting on live search; WAF managed rules on the free plan.
  • Files: the R2 bucket has no public access. Responses send Content-Disposition: attachment and Cache-Control: no-store. A later option is stamping the buyer's email in the PDF footer at render time to discourage resharing.
  • Personal data: only name, email and phone are stored. Logs redact email and phone. Abandoned orders are purged after 30 days; closed requests after 90. Deletion requests remove the person's rows and keep only anonymised order totals for tax records. CHECK retention with GRA
  • Storefront: strict Content-Security-Policy that allows only Paystack's inline script and Turnstile.
